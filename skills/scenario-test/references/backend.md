# 后端源码分析（按需加载）

本文件是 HTTP 场景编写的后端分析补充。仅当目标业务功能有可读后端源码时使用；没有后端源码、仅有接口契约，或目标是浏览器行为时跳过。

本文件只负责**从源码提取业务规则和证据**。功能卡片、场景矩阵、场景去重、DSL 编写、数据清理和执行安全，继续遵循 `author.md`、安装方的 `AI_SCENARIO_PROMPT.md` 与 `execute.md`，不在这里重复定义。

## 1. 分析范围

- 只分析用户指定功能及其直接相关调用链，不扫描整个仓库。
- 从已确认的接口入口出发，追踪会影响该功能结果的代码。
- 不要求每次覆盖所有分析维度；只深入代码中实际存在、且会影响目标功能的部分。
- 代码、注释和文档不一致时，以实际执行代码为主要依据，并记录差异。

## 2. 追踪业务调用链

按项目真实结构按需检查：

1. **Controller / 路由**：HTTP 方法、路径、参数绑定、认证与方法级权限。
2. **DTO / Validator**：字段约束、默认值、自定义校验及参数转换。
3. **Service**：业务条件、分支、状态判断、重复操作处理、异常抛出及调用顺序。
4. **Repository / Mapper**：关键查询条件、写入内容、关联数据和唯一性约束。
5. **异常与响应**：异常类型如何经过全局处理器转换为 HTTP 状态和响应结构。
6. **事务与外部依赖**：仅当目标调用链涉及事务、并发、缓存、消息队列、异步任务或第三方服务时继续追踪其可观察影响。

不要只根据方法名或注释推断行为；应找到真正决定结果的条件判断、数据操作或异常处理。无需逐行解释代码，也不追踪与目标功能无关的公共实现。

## 3. 提取业务规则与证据

每条重要规则至少记录：

| 项目 | 要求 |
|---|---|
| 规则 | 用业务语言描述实际行为 |
| 条件 | 触发该行为的关键条件 |
| 结果 | 成功、拒绝、状态变化或数据影响 |
| 证据 | 文件路径、类/方法；可定位时附代码行 |
| 可信度 | 已确认、部分确认或待确认 |

区分**代码当前实际行为**与**可能的业务预期**。证据不足时标记待确认，不把推测写成测试断言。

重点提取：
- 必填条件、数值/长度边界、枚举和自定义校验。
- 业务前置条件、禁止操作条件和异常分支。
- 状态字段及合法/非法状态转换。
- 重复提交、幂等处理及唯一性约束。
- 关键数据读写、关联关系和失败后的数据影响。
- 身份、角色、资源归属、部门或租户隔离。

## 4. 按需检查风险维度

仅在调用链存在相应机制时分析：

- **状态与流程**：重复操作、非法转换、终态保护、状态字段之间的约束。
- **数据一致性**：主子表写入、级联影响、逻辑删除、失败后部分写入。
- **事务与并发**：事务边界和回滚条件、乐观/悲观锁、并发重复请求、丢失更新。无法通过普通 HTTP 请求稳定验证的并发风险，标记为专项测试候选，不伪装成普通场景。
- **权限与隔离**：列表、详情、修改、删除是否都校验资源归属；是否可能跨用户、部门或租户访问。
- **异步与集成**：接口返回时任务是否完成、消息重复消费、重试、最终一致性及外部服务失败后的本地状态。

## 5. 映射到 HTTP 场景

只把能够通过公开 HTTP 行为验证的规则交给现有场景工作流：

- 正常操作：验证响应及后续查询到的业务结果。
- 被拒绝的操作：除验证错误响应外，尽可能通过后续查询确认数据未被错误新增或修改。
- 状态变更：验证操作前置条件、变更结果及非法操作后的状态保持。
- 数据一致性：优先通过公开查询接口验证，不直接查询或修改数据库来替代 HTTP 验证。
- 异步行为：依据源码确认的终态设计轮询断言，不使用固定等待。

内部方法调用、日志、缓存实现细节等不能从 HTTP 层观察的内容，不单独生成 HTTP 场景。第三方服务或并发行为缺乏可控测试条件时，明确标记限制和专项测试建议。

## 6. 交付给场景编写流程

将分析结果简要交给 `author.md`：

1. 关键调用链及入口。
2. 已确认的业务规则与源码证据。
3. 与目标功能相关的数据、状态、权限和集成风险。
4. 部分确认或待确认事项。
5. 可通过 HTTP 验证的候选行为。

随后由 `author.md` 统一形成场景矩阵，判断复用、增强、新建或暂不创建，并按现有规则编写场景。

## 7. 边界

- 不修改业务源码、数据库结构或项目依赖。
- 不直接执行 SQL，不通过数据库直写来准备或验证业务场景。
- 源码分析和场景编写阶段不调用业务 HTTP 接口、不启动服务；执行必须遵循 `execute.md` 的授权与安全闸门。
- 不猜测接口、错误码、响应字段、状态枚举或业务预期。
- 不强制穷举所有风险维度，不为增加测试数量而制造低价值场景。

**核心原则：从真实调用链提取业务规则，用源码证据说明规则，再交给现有 HTTP 场景工作流验证可观察的业务结果。**
