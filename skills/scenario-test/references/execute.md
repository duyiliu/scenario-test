# 场景执行、诊断与工作台

仅在用户明确要求运行或调试场景测试时使用；“生成测试”“补全场景”不是执行授权。

1. 探测并确认当前业务项目与 `config`；用探测结果中的项目内 CLI 运行 `node <cli> doctor --config <config>`。如不通过，报告诊断，不执行场景。
2. 确认用户指定的目标场景和环境（`--scenario <ID>` / `--env <KEY>`）。环境未说明时，不猜测为生产或自动选择远程环境；只在可确认是安全本地测试环境时执行，否则询问。`--all` 只在用户要求批量运行时使用；`manual: true` 的场景要求用户明确指定。
3. 场景可能创建、修改、删除业务数据。执行有副作用的接口之前，需明确具备安全测试环境、授权的测试数据和可核实的清理方式；缺失时停止，不能因为生成了场景就默认可以执行。不能在生产环境自动执行写入类测试。
4. 不把 Token/Secret 写进配置、场景文件、命令回显或报告。优先使用项目已有的环境变量注入方式，不能为了执行去提交凭据。
5. 使用**当前项目内** CLI：`node <cli> run --config <config> --env <KEY> --scenario <ID>`；如果用户明确要求批量且安全，才使用 `--all`。命令与参数遵循该项目版本的 `capabilities --json`。
6. 浏览器工作台仅当用户明确要求时通过 `node <cli> serve --config <config>` 启动（跨平台通用此命令；Windows 亦可双击项目内 `start-scenario-test.cmd`）。端口默认 4300，被占用时加 `--port <port>` 显式指定；不将公网绑定/代理地址当作默认设置。
7. 输出本次环境、执行的场景 ID、通过/失败/跳过及错误原因；敏感字段应脱敏，区分 doctor 与真正的 HTTP 执行结果。
8. 用户要求 CI 报告或批量执行时，按当前项目 `capabilities --json` 与 `--help` 使用对应参数（如 `--json`/`--junit`/`--tag`/`--data`/`--bail`/`--concurrency`），不要假设版本支持；批量与 `--all` 仍受第 2、3 条安全闸门约束。
