# 优化任务书（多轮迭代 · 持续生效）

> 本文件是 scenario-test 持续优化迭代的**持久宪法**。每轮执行 agent 从全新上下文启动，
> 唯一的使命来源就是本文件 + git log（提交信息与 CHANGELOG 即上轮交接点）。
> Hermes 编排层负责派发与审查，轮与轮之间的状态全部落在本仓库。

## 北极星

让 `@yc_yzkj/scenario-test` 对「AI 协作下的业务项目接入者」更有价值：
每轮挑一个**高价值、可验证、单轮可完成**的优化点，小步提交，全绿通过。

## 每轮工作循环

1. `git log --oneline -15` + CHANGELOG `## [Unreleased]` 恢复上下文
2. **选题**：从下方「候选优化方向」挑一项，在提交信息与报告中说明选题理由
3. **实现 + 测试**：TDD 优先；每步保持 `npm run check` 全绿
4. **文档同步**：CHANGELOG.md 顶部加 `## [Unreleased]` 条目（不带日期，发版时统一定版）
5. **提交**：一次或少量原子提交，中文提交信息，格式 `type(scope): 描述`
6. **汇报**：stdout 输出「选题理由 / 价值增量声明（本轮让业务项目接入者哪里变好、解决什么真实痛点） / 改动清单 / 验证结果 / 下一轮建议」

## 硬边界（违反即本轮作废）

- **总动作数 ≤ 40**（工具调用回合），取证类（读文件/跑测试/查 git）≤ 15。
  预算是软闸：超额须在本轮汇报中如实上报并说明理由（如修复验证必需的复跑）；
  超过上限 20%（动作 > 48 或取证 > 18）且无正当理由才作废本轮。
  注：Round 2 取证 16 次（超 1 次，修复验证必需、已自报），审查裁决为合规。
- 不 push、不打 tag、不发版：**所有提交留在本地**，push 由人工决定
- `src/contract.js` 已发布契约不可变：新增能力须 `contractVersion` 递增并保留旧字段
- 生成文件勿手改（`dist/`、`*.generated.js`、`src/version.generated.js`），改 DSL 后必须 `npm run build`
- 版本号不动（改版本=发版，超出本轮范围），CHANGELOG 只用 `## [Unreleased]`
- 不引入新 npm 依赖；Node 内置能力优先
- 不重构与选题无关的代码；不顺手改格式
- 任何一轮结束 `npm test` 必须 100% 全绿（当前基线 179/179）

## 候选优化方向（按价值评估自选，不限于此）

**A. DSL 能力扩展**（延续 v0.5.23 造数/断言/提取线）
- 断言：`contains`/`startsWith`/`endsWith`、`jsonSchema`、`each`（数组元素逐项断言）
- 提取：`jsonpath` 风格深路径、数组随机/第 N 项、响应头大小写不敏感取值
- 造数：UUID、时间戳偏移（`now + 8d`）、枚举随机（带权重）

**B. 工作台体验**（延续 0.5.x 工作台打磨线）
- 失败诊断增强：断言失败 diff 视图（expected vs actual 结构化对比）
- 场景步骤拖拽排序、场景复制、变量快速编辑
- 报告导出格式增强

**C. 性能与工程质量**
- 引擎执行路径热点优化（大响应/多步骤场景）
- 测试盲区补齐（当前 179 用例，仍有未覆盖分支）
- CLI 用户体验（错误信息可操作性、--help 分命令细化）

**D. 惊喜项**
- 若你发现任务书未列的真实痛点，可自选，但须在报告中论证价值与风险

## 双闸门验收标准（每轮顺序通过）

**① Verification Gate（复验，Hermes 做）——「做对没有」**
- `npm run check` 全绿；diff 核对硬边界；工作区干净；dist 无内容噪音

**② Review Gate（对抗审查，Codex 做）——「有没有风险 + 变好没有」**
- 硬边界/口径一致性/投射一致性/测试极性判别力/过度复杂化（既有职责）
- 价值裁决：对照 CC 汇报的「价值增量声明」一句话裁决——说不出「哪里变好」即打回重新选题
- 重 Eval（dogfooding）为阶段节点动作：每 3 轮 / 发版前，全新上下文 subagent
  模拟消费方 AI，只给 AI_SCENARIO_PROMPT + init 产物，度量一次通过率与文档盲区

**任一闸门不过 → 打回；全过 → 更新 State → 下一轮**

## 轮次与终止条件

- 计划轮数由用户动态指定；每轮双闸门顺序通过才进入下一轮
- 终止条件：候选方向做完 / 连续审查不过 / 动作预算连续超限
- 完成后人工过目全部本地提交，统一决定 push
